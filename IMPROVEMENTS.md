# Улучшения отчёта опросов

## Реализовано

- Разделены `index.html`, CSS, JavaScript, свод, детали ответов и статус обновления.
- Удалён гигантский встроенный массив `_ALL`; JSON форматируется с отступами, поэтому Git diff показывает конкретные изменённые записи.
- Первый экран загружает только компактный свод; тяжёлые детали ответов подгружаются по клику на сотрудника.
- Сохранены вкладки сотрудников и товароведов, фильтры «Все», «Не прошли», «Прошли», «Охват», поиск, управление и сортировка.
- Добавлены фильтры «Низкое качество» и «Проверить ФИО».
- Добавлены графики охвата и распределения качества S1/S2/S3.
- Для каждой сессии показываются точные выдержки ответов и исходные метрики качества.
- Формула качества опубликована прямо на сайте; отдельно указано, что это не экспертная оценка истинности.
- Сопоставление ФИО использует Bitrix ID, полный нормализованный ФИО и только затем однозначную пару «фамилия + имя».
- Один Bitrix ID с разными фамилиями больше не смешивает ответы людей; конфликт выводится в аудит.
- Два ID с одним ФИО не теряют сессии: результаты суммируются, а конфликт остаётся видимым.
- Аудит показывает варианты ФИО одного ID, несколько ID одного ФИО, дубликаты реестра и неполные имена.
- Инкрементальный индекс версии 2 хранит разобранные метрики и выдержки: при неизменном источнике все файлы берутся из локального кэша.
- Создан детерминированный `data/update-status.json`; технические cache hit/miss остаются только в локальном логе и не создают ложные коммиты.
- Добавлены Python-тесты архитектуры, качества, извлечения ответов, кэша и конфликтов идентичности; Node-проверка валидирует JS, фильтры и согласованность JSON.
- Автозадача на 08:50 обновляет только данные, запускает проверки и создаёт локальный автокоммит.
- Локальные индекс, временные файлы, логи и служебные файлы Graphify исключены из Git.

## Что ещё нужно для безопасной публикации

1. Владелец репозитория переводит `adelinaatp-source/opros` в Private или выдаёт текущей учётной записи роль Admin.
2. Отдельно проверяется видимость GitHub Pages. Если Pages остаётся публичным, его нужно отключить или перенести на закрытый корпоративный хостинг.
3. Только после закрытия доступа отправляются подготовленные локальные коммиты.
4. Автопуш включается отдельным решением после проверки неинтерактивной авторизации; `push --force` запрещён.

## Следующие полезные улучшения

- Подключить утверждённый кадровый реестр с Bitrix ID вместо исторического списка из прежнего `index.html`.
- Разобрать найденные коллизии ФИО с владельцем кадрового источника и закрепить подтверждённые соответствия в отдельной таблице правил.
- Добавить порог аномалий: резкое падение или рост числа файлов, людей или сессий останавливает автокоммит.
- Настроить уведомление только при ошибке обновления или отсутствии свежего снимка более суток.
- Добавить ротацию локальных логов и повтор задачи при временной недоступности SMB.
- После закрытия сайта добавить браузерный smoke-тест опубликованного URL.

## Ограничения

- Тексты ответов могут показать конкретику и пробелы, но автоматический индекс не определяет юридическую или методологическую истинность.
- GitHub-hosted Actions не видит локальный SMB `\\PC-BA2`; обновление должно выполняться этой Windows-задачей или изолированным self-hosted runner.
- Секреты, сетевые учётные данные и токены не должны храниться в проекте, задаче или логах.
