# Мониторинг опросов ARM

Статический внутренний отчёт строится из ресурса только для чтения
`\\PC-BA2\KB-ARM-survey`. Интерфейс, данные и детали ответов разделены, поэтому
ежедневное обновление даёт читаемый Git diff и не переписывает `index.html`
одной строкой.

## Состав проекта

- `index.html` — лёгкая оболочка сайта без персональных данных;
- `assets/styles.css` и `assets/app.js` — адаптивный интерфейс, фильтры и графики;
- `data/roster.json` — исходный кадровый реестр, перенесённый из прежнего сайта;
- `data/report.json` — компактный свод для первого экрана;
- `data/details.json` — метрики и точные выдержки ответов, загружаемые по клику;
- `data/update-status.json` — детерминированный статус последнего снимка;
- `temp/source-index.json` — локальный индекс SMB-источника;
- `out/scheduled-update.log` — локальный журнал ежедневной задачи.

## Запуск и проверка

```powershell
python scripts/update_site.py --check --json
python scripts/update_site.py
python -m unittest discover -s tests -p "test_*.py"
node scripts/validate_site.js
```

Полный локальный цикл в отдельной ветке `dashboard-quality` с тестами и автокоммитом:

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts\run-update.ps1
```

Для локального просмотра сайт нужно открыть через HTTP, потому что браузер не
разрешает `fetch()` JSON с `file://`:

```powershell
python -m http.server 8765
```

После этого открыть `http://127.0.0.1:8765/`.

## Как считается качество

- **Основной опрос по процессу** (`process_survey`): значение уверенности
  описания из документа умножается на 100;
- **доопрос без отметки «требуется уточнение»** (`gap_survey`):
  `(полностью закрытые + 0,75 × закрытые с оговорками + 0,5 × частичные) /
  всего задано × 100`;
- **фото рабочего дня** (`workday_photo`): значение полноты карты дня из
  документа умножается на 100;
- результат округляется до одного знака после запятой;
- высокий уровень — 75–100, средний — 50–74,9, низкий — ниже 50.

Коэффициенты доопроса и границы уровней являются расчётной методикой
дашборда, а не утверждённым нормативом. Индекс показывает полноту и
обоснованность материала, но не доказывает фактическую правильность ответа —
для этого нужна экспертная проверка содержания. Опросы с вопросами на
уточнение показываются отдельно и пока не включаются в сводный показатель
качества, но входят в охват как проведённые.

## Как считается количество опрошенных

1. Каждый подходящий Markdown-документ источника преобразуется в сессию.
2. Повторные документы с одинаковыми видом опроса, идентификатором сессии и
   идентификатором сотрудника считаются одной сессией; сохраняется более новая
   версия документа.
3. Сессия связывается с сотрудником реестра прежде всего по Bitrix ID. Если
   один ID связан с разными фамилиями, записи разделяются и попадают в аудит
   ФИО.
4. **Опрошенный человек** — уникальный сотрудник хотя бы с одним сохранённым
   проведённым опросом. Повторное прохождение увеличивает число опросов, но не
   число людей.
5. Технический статус источника `interrupted-partial` отображается как
   **«Есть вопросы на уточнение»**. Такой опрос входит в охват, а количество
   полностью закрытых, закрытых с оговорками, частичных, открытых и
   переадресованных вопросов показывается отдельно.
6. Из свода исключаются ручные исключения, стажёры, курьеры, служебные учётные
   записи и исключённый отдел. Их сессии сохраняются в исходной диагностике,
   но не входят в показатели дашборда.

Таким образом, число опрошенных людей нельзя получать простым подсчётом файлов
или сложением прохождений трёх видов опросов: для него используются уникальные
сотрудники после дедупликации, связывания ФИО и применения исключений.

## Автообновление

Windows-задача `Opros-Site-Update-0850` запускает обновление ежедневно в 08:50.
Скрипт проверяет чистоту рабочего дерева и активную ветку
`dashboard-quality`, индексирует изменившиеся файлы источника, пересчитывает
JSON, сверяет перенос всех сессий, запускает тесты и записывает результат в
`out/scheduled-update.log`. Локальный коммит создаётся только при изменении
данных. `git pull`, merge и `git push` намеренно отключены; отправка ветки и
слияние с `main` выполняются отдельно после проверки.

## Конфиденциальность

`data/*.json` содержит ФИО и выдержки интервью. Нельзя пушить эти файлы, пока
репозиторий и опубликованный сайт доступны публично. Перевод репозитория в
Private не гарантирует приватность GitHub Pages — доступ к Pages проверяется
отдельно.
