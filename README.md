# Автообновление отчёта опросов

Проект обновляет встроенный массив данных в `index.html` из read-only ресурса
`\\PC-BA2\KB-ARM-survey`, сохраняя существующие вкладки и фильтры сайта.

## Ручной запуск

```powershell
python scripts/update_site.py --check --json
python scripts/update_site.py
```

Полный локальный цикл с `git pull`, тестами и автокоммитом:

```powershell
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File scripts\run-update.ps1
```

Скрипт намеренно не выполняет `git push`. До отдельного разрешения изменения и
ежедневные автокоммиты остаются только в локальном клоне.

## Быстрые повторные проверки

- `temp/source-index.json` — локальный инкрементальный индекс общего ресурса:
  неизменившиеся Markdown-файлы не перечитываются по сети;
- `out/scheduled-update.log` — журнал каждого этапа ежедневной задачи и ошибок,
  `out/scheduled-bootstrap.log` — ранние ошибки запуска PowerShell;
- `graphify-out/graph.json` — служебный граф кода для быстрого анализа проекта;
  после изменения скриптов обновляется командой
  `graphify update . --no-cluster`;
- `temp/` и `out/` не попадают в Git, так как индекс и журнал содержат локальные
  служебные данные.

## Источник и правила подсчёта

- `process_survey` → основной опрос (`s1`);
- `gap_survey` со статусом `completed` → доопрос (`s2`);
- `workday_photo` → фото рабочего дня (`s3`);
- повторяющиеся методологические документы одной сессии дедуплицируются по
  `scenario + session_id + ФИО`;
- штатный реестр берётся из текущего `index.html`, а счётчики прохождений каждый
  раз пересчитываются с нуля по общему ресурсу;
- новый участник, которого нет в прежнем реестре, добавляется по метаданным
  интервью; неоднозначные сопоставления отражаются в диагностике.

## Конфиденциальность

Источник и `index.html` содержат ФИО сотрудников. Репозиторий и GitHub Pages
публичны, поэтому публикацию необходимо отдельно согласовать.
